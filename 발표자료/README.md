# 발표자료 취합 폴더

팀 결과보고서(`결과보고서_4팀(ReMedi).pptx`)에 반영할 **스쿼드별 발표 자료를 모아두는 곳**이다.

## 구조

```
발표자료/
├── README.md                  ← 이 파일. 규칙과 인덱스만. 거의 바뀌지 않는다
├── D스쿼드_LLM-RAG_상세.md      ← 스쿼드별 문서 (담당자만 수정)
└── D스쿼드_추가장표_2장.pptx     ← 덱에 붙일 장표 파일
```

**스쿼드별 문서 하나가 그 스쿼드의 단일 창구다.** 각 문서는 세 부분을 갖는다.

1. **작업 상세** — 덱에는 요약만 들어가므로, 실측값·근거 파일 경로·질의응답 대비 내용을 여기 남긴다
2. **반영 대기 목록** — 덱에 아직 안 들어간 항목의 체크리스트
3. **증분 이력** — 날짜별로 무엇이 추가·변경됐는지

> **대기 목록과 증분 이력을 이 README가 아니라 각 스쿼드 문서 안에 두는 이유**: 4명이 병렬로
> 작업하므로 공용 파일 한 곳에 모으면 갱신할 때마다 충돌한다. 스쿼드별로 나누면 서로 같은
> 파일을 건드리지 않는다.

---

## 이 폴더를 갱신하는 에이전트에게

**입력**: 각 스쿼드 문서의 "반영 대기 목록"
**할 일**: 미완료 항목을 덱에 반영하고, **반영한 항목의 체크박스를 그 스쿼드 문서에서** 채운 뒤 커밋

**규칙**
- `⚠️` 가 붙은 항목은 **사실관계 오류 수정**이다. 새 내용 추가보다 먼저 처리한다.
- 스쿼드 문서는 **해당 담당자만** 수정한다. 단, 위 "할 일"의 체크박스 채우기는 예외로 허용한다.
- 덱에 넣을 문장은 각 문서에서 그대로 가져다 쓸 수 있게 써 있다. **새로 지어내지 않는다.**
- 수치를 옮길 때는 문서에 적힌 근거 파일 경로를 함께 확인한다. **근거가 없는 숫자는 넣지 않는다.**
- 담당이 갈리는 내용(문서에 "출처 구분" / "담당 구분"으로 표시됨)은 임의로 합치지 말고 리더에게 확인한다.

## 인덱스

| 스쿼드 | 담당 | 문서 | 범위 |
|---|---|---|---|
| D | 박지은 | `D스쿼드_LLM-RAG_상세.md` | LLM / RAG / 챗봇 — 덱 ⑩~⑮ |
| A | 심복규 | (없음) | 인증 / 보안 / 관리자 — 덱 ⑥~⑨ |
| B | 이은호 | (없음) | 복약 인식 / 인프라 — 덱 ①~⑤ |
| C | 정다이 | 리포 루트 `발표자료_완전버전.md` | 알림 / 개인화 — 덱 ⑭~⑮(현행 번호) |

- **C스쿼드 문서는 아직 리포 루트에 있다.** 소유자만 옮길 수 있어 그대로 두었다 — 취합 시 누락되지 않도록 여기 적어둔다.
- A·B스쿼드는 상세 문서가 아직 없다. 덱 본문이 유일한 출처이므로, 질의응답 대비가 필요하면 담당자가 이 폴더에 추가한다.

## 팀 공통 대기 항목

특정 스쿼드에 속하지 않아 리더 판단이 필요한 것.

- [ ] **차별화 / 기존 유사 서비스 비교 슬라이드 신설** — 원본 템플릿 안내의 명시적 요구사항(`프로젝트 주제의 특화 포인트, 기존 유사 서비스와 차별화된 내용 제시`)인데 현재 덱에 관련 서술이 0건이다. 평가기준 1-1·1-3 양쪽에 걸린다.
- [ ] **화면 흐름도 + 주요 기능별 접근 단계 수 표** — 평가기준 1-3(화면 흐름도 포함) / 4-1 / 4-3(3~5단계 접근)을 한 장으로 동시에 충족할 수 있다.
- [ ] **계층 아키텍처 다이어그램** — 평가기준 2-3. 현재 3p의 "프로젝트 구조"는 스쿼드 편성 설명이라 아키텍처가 아니다.
- [ ] **16p 배포 장애 서술의 마무리** — 문제 대응 역량으로는 가점이지만, 평가기준 5-3은 "오류 없이 정상 동작"이 만점이다. "해소 후 현재 무장애 운영 중"으로 닫아야 감점을 피한다.

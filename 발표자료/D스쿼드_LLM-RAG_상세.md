작성: 박지은 (D스쿼드) · 최종 갱신 2026-08-04

팀 결과보고서 덱의 **04. 프로젝트 수행 경과 ⑩~⑮** 에 해당하는 내용을 상세히 정리한 문서다.
덱에는 요약만 들어가므로, 발표 질의응답과 채점 근거 대조를 위해 실측값·파일 경로를 함께 남긴다.

## ⚠️ 먼저 — 현재 덱의 사실관계 오류 1건 (수정 필요)

**덱 19p(⑪ RAG 아키텍처)와 20p(⑫ 문제 진단 및 재설계)가 `QueryClassification`을 현재 구조로 서술하고 있으나, 이 컴포넌트는 지금 코드에 없다.**

- 19p 파이프라인 다이어그램에 `QueryClassification / 2축 구조화 분류 (disease / is_information_request)` 박스가 있음
- 20p 재설계 결과가 `QueryClassification 2축 구조화 분류로 전환` 으로 서술됨
- 실제: `grep -rn "QueryClassification\|is_information_request"` → **0건**. T-LLM-7-3-2에서 DUR·논문 파이프라인을 `/agent/chat` 단일 스트리밍으로 통합할 때 제거됐고, 질환 판별은 규칙 기반 `ai_worker/services/disease_query_resolver.py::resolve_diseases()` 가 맡는다.

**수정 방향**: ⑫는 "그 시점의 재설계 과정"으로 시제를 분명히 하고(그대로 사실), ⑪ 다이어그램의 박스는 현재 구현대로 **`disease_query_resolver` 규칙 기반 질환 판별**로 바꿔야 한다. 심사위원이 코드에서 확인하려 하면 바로 드러나는 항목이다.

### 의학 논문 (비구조화)
- 5대 질환(암 / 심장질환 / 뇌혈관질환 / 당뇨 / 간질환) PubMed 논문 **총 740건** — `ai_worker/source/*.json` (질환별 140~158건)

- PMID 기준 증분 색인으로 중복 재임베딩 방지
- 실측 기반 설계 검증: 초록 결합 텍스트의 **98.3%가 1,000자를 초과**함을 확인하고 파라미터에 반영

### DUR 안전성 (구조화)
- 브랜드명↔성분명 매칭 브릿지 **8,095건 → 49,624건 (6배)** — `ai_worker/source/_item_ingredient_map.csv`

  - 해결한 버그: "인데놀" 등 브랜드명으로만 불리는 약이 RAG 검색에서 통째로 누락되던 문제
- 성분-품목 매핑 49,669건 / 32,296개 품목 (커버리지 80.0%)

> **출처 구분**: DUR 원본 데이터의 MySQL 이관(약 98만 건)은 **B스쿼드(이은호) 산출물**이다.

## ⑪ RAG 아키텍처

- **이원화 컬렉션**: ChromaDB 안에 구조화(DUR)와 비구조화(논문)를 별도 컬렉션으로 분리 — `ai_worker/ingest/sources.py`
- **단일 스트리밍 엔드포인트**: `POST /agent/chat` 하나로 DUR 검색 + 논문 검색 + 답변 생성 처리, `{"type":"sources"}` → `{"type":"token"}` 순차 스트리밍 — `ai_worker/tasks/chat_agent.py::stream_chat_answer`
- **임베딩**: 로컬 HuggingFace `intfloat/multilingual-e5-large` (외부 API 키·네트워크 불필요)
- **유사도 임계값** (Chroma L2 거리, 낮을수록 유사): DUR `0.35`, 논문 `0.40` — `ai_worker/core/config.py`
- **검색 전처리**: 질환 판별 `disease_query_resolver.resolve_diseases()`, 약품명·성분명 해석 `drug_name_resolver` (둘 다 규칙 기반)

## ⑫ 문제 진단 및 재설계 (당시 과정)

| 단계 | 내용 |
|---|---|
| 초기 구조 | LLM이 자유롭게 판단해 검색 도구를 호출하는 에이전트 루프 |
| 실패 발견 | 자체 평가셋(5질환 × 2문항)에서 "뇌졸중", "지방간" 같은 표현 변형에 도구 호출이 거부됨 |
| 1차 시도 | Query Rewriting 적용 → "지방간", "심장마비"류는 여전히 실패 (부분 개선에 그침을 실측 확인) |
| 근본 원인 | 표현 문제가 아니라 "LLM의 자유판단 호출 구조" 자체 |
| 재설계 | 2축 구조화 분류로 전환 + 도구 호출 강제, 에이전트 루프 제거 |
| 검증 | "심장이 쫄리다" 같은 한국어 신체 관용구 오탐까지 잡고 16문항 실측 통과 |

> 이후 T-LLM-7-3-2 통합에서 이 분류기는 제거되고, 같은 역할을 규칙 기반 `disease_query_resolver`가
> 맡는 구조로 바뀌었다. 발표에서는 **"당시의 진단·재설계 과정"**으로 말해야 정확하다.

## ⑬ 평가 및 최적화

- **임베딩 벤치마크**: 골든셋 40문항 recall@3 — OpenAI `text-embedding-3-small` **0.85** vs 로컬 HF `multilingual-e5-large` **1.0** → 로컬 모델 채택
  - 근거 파일: `ai_worker/scripts/benchmark_embeddings.py`, `ai_worker/tests/fixtures/embedding_golden_set.json`
- **임계값 실측 재조정**: 관련/무관 문서의 실제 거리 분포를 측정해 확정

- **Langfuse 관측성 (2단계)**

  - 두 단계 모두 no-op 방식(키 미설정 시 완전 무회귀) — `ai_worker/core/observability.py`

## ⑮ 피드백 루프 + 응답 일관성 검증

### 사용자 피드백 → 저장 → 개선 (평가기준 3-4)
- 챗봇 답변마다 👍/👎, 과거 대화 이력에서도 평가 가능 — `POST /chat/messages/{id}/feedback`
- 저장: `chat_message_feedbacks` (message_id UNIQUE, 재평가 시 값 갱신) + `chat_messages.trace_id`
- 같은 피드백을 **Langfuse trace에 점수로 부착** (`user_feedback`, 👍=1.0 / 👎=0.0, 코멘트 포함)
- 설계: trace_id를 프론트에 노출하지 않고 서버가 message_id → trace_id를 조회해 전송. 관측 실패가 사용자 요청을 막지 않음(저장 성공 시 즉시 200)
- **개선 실사례**: 일반 성인의 장기복용 질문에 임신부 전용 DUR 경고가 구분 없이 섞인 답변을 👎로 포착 → trace를 열어 **검색은 정상이고 프롬프트가 원인**임을 분리 → 대상 한정 경고를 구분해 설명하도록 시스템 프롬프트 보강 → 재실행으로 개선 확인. **임계값은 건드리지 않았다.**
- 관련 문서: `docs/tasks/T-LLM-2-langfuse-user-feedback.md` (PR #343)

> **팀 내 다른 피드백 구현**: 습관·식단 추천 "이유"에 대한 👍/👎 루프는 **C스쿼드(정다이)** 산출물이다
> (`app/models/reason_feedback.py`, `frontend/src/components/common/ReasonFeedback.tsx`, dev 머지 완료).
> 발표에서는 "AI 출력 전반에 피드백 루프를 깔았다(챗봇 답변 + 추천 이유)"로 묶으면 근거가 강해지지만,
> 두 구현의 담당자가 다르다는 점은 명확히 하는 것이 좋다.

### 동일 입력 반복 일관성 (평가기준 3-3)
측정 도구: `ai_worker/scripts/measure_response_consistency.py`
(층 1·2는 네트워크·API 키 없이 실행 가능 — 발표 현장 재현 가능)

파이프라인의 결정성이 층마다 다르게 **설계**돼 있으므로, "전체가 똑같은가"가 아니라
"결정적이어야 할 층이 실제로 결정적인가"를 측정했다.

| 층 | 대상 | 결과 (질문 5개 × 5회 × 2프로세스) |
|---|---|---|
| 1 | 규칙 기반 질의 해석 (`resolve_diseases`) | **완전 일치** |
| 2 | 벡터 검색 — 문서 집합 + **유사도 점수까지** | **완전 일치**, 두 프로세스 결과 JSON 바이트 동일 |
| 3 | LLM 생성 — 출처(sources) 목록 | **5/5 일치** |

**임계값 경계 사례 (가장 단단한 근거)**: "지방간" 질문의 후보 논문 5건 중 두 건이 컷오프 0.40 양쪽 0.2% 이내에 있었다.

| PMID | 점수 | 판정 |
|---|---|---|
| 40005465 | 0.3982325792312622 | 임계값 아래 0.0018 → **포함** |
| 41808270 | 0.4012205600738525 | 임계값 위 0.0012 → **제외** |

10회 반복에서 한 번도 뒤바뀌지 않았고 점수가 소수점 17자리까지 동일했다.
비결정성이 조금이라도 있으면 이 경계 문서가 들락날락해야 하므로, 깔끔하게 떨어지는
사례보다 훨씬 강한 결정성 증거다.

### 체감한 한계
반복 측정으로 답변 편차의 원인까지 특정하고 조치했으나, **현재 코퍼스 규모(논문 740건,
질환별 140~158건)로는 답변 품질 자체의 유의미한 개선 프로세스를 구축하기에 한계가 있었다.**
논문·기사·관련 데이터를 확충하면 검색 품질을 통해 답변 품질이 향상될 것으로 기대한다.

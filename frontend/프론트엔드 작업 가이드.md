# 프론트엔드(React) 작업 가이드

> 백엔드의 "도메인 구조 작업 가이드.md"와 짝이 되는 문서입니다. 폴더 구조를 백엔드 도메인과 최대한 1:1로 맞췄습니다.

---

## 1. 뭘로 만들었나요?

**Vite + React + TypeScript + Tailwind CSS + React Router + TanStack Query + Zustand** 조합입니다. 각 도구가 뭘 하는지 궁금하시면 `React와 프론트엔드 관계 설명.md` 문서를 먼저 참고해주세요.

---

## 2. 시작하는 법

```bash
npm install
cp .env.example .env    # 필요하면 VITE_API_BASE_URL 수정
npm run dev
```

- 백엔드가 `http://127.0.0.1:8000`에서 돌고 있으면, `vite.config.ts`의 프록시 설정 덕분에 CORS 신경 안 쓰고 바로 API가 붙습니다.
- `npm run build` → 프로덕션 빌드
- `npx tsc --noEmit` → 타입 체크만 따로 실행

---

## 3. 폴더 구조 & 무엇이 어디에 있나

```
src/
├── api/
│   ├── client.ts            ← axios 인스턴스. JWT 자동 첨부 + 401 시 자동 재발급 처리
│   └── endpoints/            ← 도메인별 API 호출 함수 (15개 도메인 전부 이미 만들어져 있음)
│       ├── auth.ts, user.ts, schedule.ts, record.ts, medication.ts ...
│
├── types/index.ts            ← 백엔드 스키마와 대응하는 TypeScript 타입 (전 도메인 포함)
│
├── store/
│   └── authStore.ts          ← 로그인 상태 전역 관리 (Zustand)
│
├── routes/
│   ├── router.tsx             ← 전체 라우트(URL ↔ 화면) 정의
│   └── ProtectedRoute.tsx     ← 로그인 안 했으면 /login으로 튕기는 가드
│
├── components/ui/
│   ├── Layout.tsx              ← 사이드바 + 상단 메뉴 (공통 뼈대)
│   └── PlaceholderPage.tsx     ← 아직 안 만든 화면에 "TODO" 표시하는 임시 컴포넌트
│
└── features/                   ← 도메인별 실제 화면 (백엔드 domains/와 폴더명 동일)
    ├── auth/                   ✅ 완성 (로그인/회원가입)
    ├── schedule/               ✅ 완성 (목록+등록, React Query 패턴 예시)
    ├── emergency_card/         🚧 PlaceholderPage만 있음
    ├── pwa_subscription/       🚧
    ├── support_group/          🚧
    ├── record/                 🚧
    ├── medication/             🚧
    ├── intake_log/             🚧
    ├── food_intake/            🚧
    ├── drug_food_interaction/  🚧
    ├── health_metric/          🚧
    ├── appointment/            🚧
    ├── symptom_log/            🚧
    ├── chat/                   🚧
    └── generated_guide/        🚧
```

**핵심 원칙**: API 호출 함수(`api/endpoints/`)와 타입(`types/`)은 이미 15개 도메인 전부 완성돼 있습니다. 화면(`features/`)만 비어있는 상태입니다. 즉, "API 연동"을 새로 고민할 필요 없이 "화면만 만들면" 됩니다.

---

## 4. 새 화면을 만드는 5단계

예: **응급 의료 카드(emergency_card)** 화면을 만든다면 —

1. **API 함수 확인** — `src/api/endpoints/emergencyCard.ts`를 엽니다. `get()`, `upsert()` 함수가 이미 있습니다. 새로 만들 필요 없습니다.
2. **훅 만들기** — `src/features/schedule/useSchedules.ts`를 복사해서 `src/features/emergency_card/useEmergencyCard.ts`로 만들고, React Query의 `useQuery`(조회) / `useMutation`(등록·수정)으로 감쌉니다.
3. **화면 만들기** — `src/features/schedule/SchedulePage.tsx` 구조를 그대로 참고해서 `EmergencyCardPage.tsx`를 채웁니다. 지금은 `PlaceholderPage`만 렌더링하고 있는 부분을 실제 폼/목록으로 교체하면 됩니다.
4. **디자인 맞추기** — `var(--panel-bg)`, `var(--accent-cyan)` 같은 CSS 변수를 `style={{ }}`로 쓰는 방식을 그대로 따라 하면 톤이 자동으로 맞습니다 (변수는 `src/index.css`에 정의). Tailwind 유틸 클래스(`flex`, `rounded-xl`, `p-4` 등)와 섞어 써도 됩니다.
5. **라우트는 손댈 필요 없음** — 이미 `router.tsx`에 다 등록되어 있어서, 컴포넌트 내용만 채우면 사이드바 메뉴 클릭 시 바로 반영됩니다.

## 5. 인증 흐름 — 꼭 알아야 할 것

- 로그인 성공 시 `access_token`은 **메모리(Zustand)에만** 저장됩니다. `localStorage`에 안 넣는 건 실수가 아니라 **의도된 설계**입니다 (XSS 공격 시 탈취 위험을 줄이기 위함).
- `refresh_token`은 브라우저가 자동 관리하는 **HttpOnly 쿠키**라 JS 코드로 직접 읽거나 쓸 수 없습니다. 이것도 정상입니다.
- 새로고침하면 `access_token`이 메모리에서 사라지는데, `App.tsx`가 시작할 때 자동으로 `/users/refresh`를 호출해서 다시 받아옵니다.
- API 호출 중 401(토큰 만료)이 오면 `api/client.ts`가 **자동으로 갱신을 시도하고 원래 요청을 재시도**합니다. 그래도 실패하면 로그인 페이지로 보냅니다. **이 로직은 이미 다 되어 있으니 건드릴 필요 없습니다.**

## 6. 수정할 때 주의사항

### ⚠️ `api/endpoints/`의 함수 시그니처를 함부로 바꾸지 마세요
다른 팀원이 이미 그 함수를 쓰고 있을 수 있습니다. 요청/응답 형태를 바꿔야 한다면, 먼저 백엔드 `schema.py`가 실제로 그렇게 바뀌었는지 확인하고 `types/index.ts`도 같이 맞춰주세요.

### ⚠️ `PlaceholderPage`를 지우고 화면을 새로 만들 때, import 경로를 확인하세요
`features/도메인명/화면이름.tsx` 파일은 `router.tsx`에서 이미 import되고 있습니다. 파일명이나 컴포넌트 이름을 바꾸면 `router.tsx`도 같이 고쳐야 합니다.

### ⚠️ 백엔드에 없는 기능은 프론트에서 못 만듭니다
아래는 **백엔드 작업이 먼저 필요한** 항목입니다 (프론트에서 아무리 잘 만들어도 실제 데이터가 안 옵니다):
- Google 소셜 로그인 (OAuth 콜백 라우트 없음)
- 알약 이미지 검색 (pgvector 보류 상태 → 항상 빈 결과)
- AI 챗봇 실시간 스트리밍 (SSE 미구현 → 일반 JSON 응답만 옴)
- 건강지표 / 병원예약 / 증상 **목록 조회** (등록 API만 있고 조회 API가 없음)

이 기능이 필요하면, 먼저 백엔드 해당 도메인의 `router.py`에 있는 `# TODO(조원 구현)` 주석부터 채워야 합니다.

### ⚠️ CSS 변수를 직접 바꾸지 말고 `index.css`에서만 바꾸세요
디자인 톤(색상 등)을 전체적으로 바꾸고 싶으면 각 컴포넌트를 하나씩 고치지 말고 `src/index.css`의 `:root` 변수만 바꾸면 전체가 한 번에 바뀝니다.

## 7. 막히면 여기부터 확인

| 증상 | 확인할 것 |
|---|---|
| 화면에 아무것도 안 뜸 | 브라우저 콘솔에 에러 있는지, `npm run dev` 터미널에 에러 있는지 |
| API 호출이 다 401 남 | 로그인이 실제로 됐는지 (`useAuthStore`의 `accessToken` 값 확인) |
| 로그인은 되는데 새로고침하면 로그아웃됨 | 백엔드가 쿠키를 정상적으로 내려주는지 (`Set-Cookie` 헤더), `withCredentials: true` 옵션이 빠지지 않았는지 |
| 새로 만든 화면이 사이드바에 없음 | `components/ui/Layout.tsx`의 `NAV_ITEMS` 배열에 추가했는지 |
| 새로 만든 화면 URL로 가도 빈 화면 | `routes/router.tsx`에 라우트 등록했는지 |
| 타입 에러가 계속 남 | `types/index.ts`가 백엔드 `schema.py`와 실제로 일치하는지 |

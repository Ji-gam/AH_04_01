# LLM 게이트웨이 사용 가이드 (`AIWorkerGateway`)

`app/services/ai_worker_gateway.py`에 있는 얇은 유틸리티. 역할은 단순하다: **프롬프트와
원하는 출력 형태(스키마)를 건네주면, OpenAI를 호출해서 그 형태에 맞는 결과를 돌려준다.**
그 이상도 이하도 아니다 — 이 요청이 무슨 도메인 것인지, 왜 필요한지는 전혀 모른다(도메인
지식 0). 편하게 갖다 쓰면 되는 얇은 통로다.

## 쓰기 전에 먼저: 이거 정말 LLM이 필요한 문제인가?

호출에는 항상 비용(토큰/레이턴시)과 리스크(할루시네이션)가 따른다. 아래를 먼저 통과시켜본다.

1. **입력이 매번 달라지는가, 아니면 정해진(유한한) 집합인가?**
   유한한 집합(참조 테이블, 마스터 데이터 등)이면 → 요청마다 부르지 말고, 한 번만 계산해서
   저장해두고 그 이후로는 저장된 값만 읽는 쪽을 먼저 고려한다.
2. **정확한 키로 바로 찾을 수 있는 데이터인가?**
   이름/코드 같은 정확한 키가 있으면 → 그냥 사전(dict)/DB 조회로 충분하다. 검색도 생성도
   필요 없다.
3. **같은 상호작용(클릭, 펼치기, 페이지 이동 등)이 반복될 때마다 새로 호출되는 구조는
   아닌가?**
   한 번의 조회에서 필요한 걸 다 받아온 뒤, 그다음 상호작용은 이미 받은 데이터를 화면에서
   다루는 것으로 처리한다. 상호작용 한 번마다 다시 부르지 않는다.
4. **유한한 데이터셋에 대한 "커버리지 개선" 문제인가, 진짜 새로운 입력에 대한 "일반화"가
   필요한 문제인가?**
   전자라면 규칙 기반(사전 확장, 동의어 묶음 등)이 더 안전하고 감사하기 쉽다(할루시네이션
   위험이 구조적으로 없음). LLM은 후자 — 미리 다 나열해둘 수 없는 다양한 입력에 대응해야
   할 때 쓴다.
5. **위를 다 통과해서 LLM이 필요하다는 결론이 나면** — "요청 들어올 때마다 실시간으로
   부를지, 원본이 안 바뀌는 한 한 번 계산해서 캐싱해둘지"를 정한다. 원본이 안 바뀐다면
   무조건 후자다.

## 입구 두 개

어느 쪽을 쓸지는 **"내가 이미 근거 텍스트를 갖고 있는가, 아니면 뭐가 관련 있는지부터
찾아야 하는가"**로 정해진다.

### 1. 순수 생성 — 이미 갖고 있는 텍스트를 가공한다 (검색 불필요)

이미 손에 쥔 텍스트(참조 문서 한 건, 이미 받아온 API 응답 등)에서 뭔가를 뽑아내거나
바꾸고 싶을 때. 찾는 과정이 없으므로 `call_structured()`만 있으면 된다.

```python
class FoodItem(BaseModel):
    name: str
    detail: str

class ExtractionResult(BaseModel):
    items: list[FoodItem]

result = await gateway.call_structured(
    system_prompt=(
        "아래 원문에 실제로 언급된 음식/음료만 찾아 나열하라. "
        "원문에 없는 내용은 추가하지 마라(동의어는 하나로 묶어라)."
    ),
    user_input=원문_텍스트,       # 이미 갖고 있는 텍스트
    schema=ExtractionResult,
)
```

### 2. RAG — 뭐가 관련 있는지부터 찾고, 그걸 근거로 생성한다

질문/키워드만 있고 어떤 자료가 관련 있는지는 모를 때. `search()`로 먼저 찾고, 그 결과를
근거로 삼아 `call_structured()`(또는 자유 텍스트가 필요하면 스트리밍 LLM 호출)에 넘긴다.

```python
chunks = await gateway.search("졸피뎀 임부 관련 주의사항")   # 1) 근거부터 찾는다
context_text = "\n".join(c["content"] for c in chunks)

class Answer(BaseModel):
    summary: str
    sources: list[str]

result = await gateway.call_structured(                     # 2) 그 근거만 갖고 답하게 한다
    system_prompt=(
        f"아래 근거 자료만 바탕으로 답하라. 근거에 없으면 '자료 없음'이라고 답하라.\n"
        f"근거 자료:\n{context_text}"
    ),
    user_input="졸피뎀을 임신 중에 먹어도 되나요?",
    schema=Answer,
)
```

`search()`에서 나온 결과가 부실하거나 관련 없는 것만 나온다면, 프롬프트를 손봐서 해결할
문제가 아니라 **벡터DB에 그 자료가 안 들어있거나 부족하다는 신호**다 — 이 경우 자료를
보강(인제스트)하는 게 먼저다.

(구조화된 스키마가 필요 없고 자유 텍스트 스트리밍이면 될 때는 1)의 결과를 `llm_stub.py`
쪽 스트리밍 호출에 근거로 끼워 넣는 방식도 쓸 수 있다.)

## 에러

- `AIWorkerUnavailableError`: 응답 없음(타임아웃)/API 키 없어 애초에 생성 불가
- `AIWorkerInvalidRequestError`: 요청 자체가 잘못됨
- `AIWorkerProcessingError`: 응답은 왔는데 기대한 형태가 아님

빈 결과(정상, 매칭 0건)와 예외(실패)는 구분한다 — 실패를 빈 결과로 조용히 둔갑시키지 않는다.

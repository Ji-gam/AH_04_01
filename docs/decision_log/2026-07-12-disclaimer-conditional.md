# 2026-07-12 — 면책조항 정책 확정: "전 응답 강제"에서 "의료 관련 조건부"로

> 배경: `docs/review/2026-07-11-codebase-review.md` §7·§10(H4-b)이 지적한 **정책↔코드 불일치**를
> 해소하기 위한 결정 기록. AGENTS.md §8은 "모든 LLM 응답에 면책조항 강제 노출"이라고
> 적혀 있었으나, 실제 구현(`chat_service.py`)은 의료 관련 판정이 참일 때만 붙이고 있었다.

## 결정

면책조항 노출 정책을 **"의료 관련으로 판정된 응답에 조건부 노출"** 로 확정한다.
(문서를 코드에 맞춘다 — 코드 동작은 유지.)

## 근거

- 잡담/비의료 응답("오늘 날씨 좋네요")에까지 의학 면책조항을 붙이는 것은 사용자 경험상
  부자연스럽고, 면책조항의 신호 가치(진짜 의료 정보라는 표시)를 희석한다.
- 실제 위험 지점은 **의료 응답에 면책조항이 누락되는 것**이지, 비의료 응답에 붙는 것이 아니다.
  따라서 판정 정확도(누락 방지)를 높이는 방향으로 관리한다.

## 구현 현황 (코드가 단일 출처)

- 판정: `chat_service._check_if_medical_related_via_llm` (LLM 분류 + 키워드 폴백)이 참일 때만 노출.
- 전달 방식: 스트리밍 응답에서는 **`done` 이벤트의 `disclaimer` 필드**로 전달한다
  (`chat_service.stream_reply`). 응급 폴백(`emergency_fallback`) 경로에서도 동일 텍스트를 노출한다.
- `safety_service.apply_disclaimer(reply)`는 문자열 말미에 붙이는 헬퍼로, 스트리밍(필드 전달)
  방식과 맞지 않아 챗 경로에서는 사용하지 않는다. 비스트리밍 텍스트 응답용으로만 유지한다.
- 면책조항 문구의 단일 출처는 `safety_service.DISCLAIMER_TEXT`.

## 후속 (별도 작업)

- 판정 함수(`_check_if_medical_related_via_llm`)의 config 경유·예외 로깅·키워드 목록 단일화
  정리는 T-LLM-1-chat-cleanup에서 다룬다(정책 변경 아님, 소스 정리).
- 오분류로 인한 의료 응답 면책조항 누락을 줄이기 위한 키워드/프롬프트 튜닝은 지속 과제.

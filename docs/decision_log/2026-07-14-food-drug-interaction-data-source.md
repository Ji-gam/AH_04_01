# 2026-07-14 — 음식-약물 상호작용 데이터 소스 확정 (T-DOC-3/T-DOC-4)

> 그날 팀 전체의 결정을 모아두는 날짜 파일(`2026-07-14.md`)과 달리, 이 문서는 B스쿼드(복약인식/
> 알림) 담당 영역(음식-약물 상호작용 데이터 소스)에 대해 단독으로 내린 결정이라 별도 파일로 뺐다
> (`2026-07-10-ai-rag-worker.md`와 동일한 관례).

## 배경

T-DOC-2에서 "음식(13번)" 탭 안내 카드를 e약은요(`DrbEasyDrugInfoService`) 응답의 `intrcQesitm`
자유 텍스트 + 키워드 필터로 채웠는데, 이 필드는 약물-약물 상호작용과 음식 상호작용이 섞여 있어
정확도에 한계가 있었다. 더 정확한 데이터 소스가 있는지 조사했다.

## 조사 결과

- **식약처 DUR API**(`DURPrdlstInfoService`, 병용금기·특정연령대금기·임부금기·용량주의·투여기간주의·
  노인주의·효능군중복주의·서방정분할주의·DUR품목정보 9개 카테고리)에는 음식 전용 카테고리가 없다.
- **공공데이터포털(data.go.kr)**에는 음식-약물 상호작용을 전담하는 구조화된 API/데이터셋이
  존재하지 않는다.
- **약학정보원(health.kr) 약물-음식 상호작용 검색**(`health.kr/interaction/food.asp`)은 성분/
  제품명 기준 조회가 가능한 유일한 전용 서비스지만, 공개 API 없이 웹 검색 폼만 제공하고 사이트
  자체가 "참고용"이라고 명시한다 — 크롤링은 이용약관 확인이 별도로 필요해 이번 범위에서 채택하지 않았다.
- **식약처가 직접 발간한 PDF 가이드북**("약과 음식 상호작용을 피하는 복약안내서", 식품의약품안전
  평가원, 2016.09.30)이 정부 발간 자료 중 가장 구조화하기 좋은 소스였다. 질환/약효군 단위로
  대표 성분과 음식물·음주 상호작용을 서술한다.

## 후속 작업 (범위 밖, 별도로 진행)

- PDF 41-42페이지 요약표를 별도로 파싱해 참조 테이블 커버리지를 보강할지 여부
- V1(사전 매칭) 커버리지가 부족하면 LLM 기반(V2) 음식명 추출로 교체 — `_extract_food_items` 함수
  시그니처(원문 텍스트 -> FoodItem 목록)만 유지하면 내부 구현 교체 가능하도록 이미 분리해둠
  (`app/services/medication_service.py`)
- "알코올"/"음주"처럼 사전에 유사어를 모두 등록해 같은 문장이 여러 칩으로 중복 노출되는 경우가
  있음 — 사전에 유의어 그룹 도입 여부 검토

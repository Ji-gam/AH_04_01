# 도메인 구조 작업 가이드

> 백엔드가 "종류별(routers/models/schemas 따로)" 구조에서 "기능별(도메인별)" 구조로 바뀌었습니다.
> 이 문서는 **왜 바뀌었는지, 어디에 뭐가 있는지, 새로 추가할 때 어떻게 하는지, 수정할 때 뭘 조심해야 하는지**를 정리한 문서입니다.

---

## 1. 뭐가 바뀐 건가요?

**예전 (종류별)**
```
backend/
├── routers/
│   ├── user_routers.py
│   ├── record_routers.py
│   └── ... (전체 도메인의 라우터가 한 폴더에 다 모여있음)
├── models/
│   ├── user_model.py
│   ├── medical_model.py
│   └── ...
├── schemas/
│   └── ...
└── services/
    └── ...
```
→ "user 관련 코드를 보고 싶다" → `routers/`, `models/`, `schemas/`, `services/` 4개 폴더를 왔다갔다 해야 함.

**지금 (도메인별)**
```
backend/
├── core/                    ← DB 연결, 환경설정, 로그인 등 "도메인이 아닌" 공통 설정
│   ├── database.py
│   ├── config.py
│   └── dependencies.py
│
├── utils/                   ← 여러 도메인이 같이 쓰는 유틸 (비밀번호 해싱, 로깅 등)
│   ├── security.py
│   ├── logger.py
│   └── helpers.py
│
└── domains/                 ← 기능(도메인)별로 폴더가 나뉨
    ├── auth/          회원가입/로그인
    ├── user/          사용자 정보/프로필
    ├── record/        진료기록
    ├── guide/         복약 가이드 + OCR
    ├── chat/          AI 상담 챗봇
    ├── guardian/      보호자 관리
    ├── verification/  복약 인증
    ├── health/        혈당/식단 기록
    ├── schedule/      복약 스케줄
    ├── hospital/      병원/예약
    ├── health_extra/  증상/비상연락처
    └── drug/          의약품 정보 (MFDS 연동, 테스트용)
```
→ "user 관련 코드를 보고 싶다" → `domains/user/` 폴더 하나만 열면 끝.

**장점**: 팀원이 각자 다른 도메인 폴더를 맡으면 서로 다른 파일을 건드리게 돼서 git 충돌이 훨씬 줄어들어요. "이 기능 어디 있지?"를 찾는 시간도 줄어듭니다.

## 2. 도메인 폴더 안에는 뭐가 들어있나요?

도메인 폴더 하나(`domains/xxx/`) 안에는 보통 이런 파일들이 있어요:

| 파일 | 역할 | 예시 |
|---|---|---|
| `router.py` | API 엔드포인트 (URL, HTTP 메서드) 정의 | `@router.post("/", ...)` |
| `model.py` | DB 테이블 정의 (SQLAlchemy) | `class User(Base): ...` |
| `schema.py` | API 요청/응답 형태 정의 (Pydantic) | `class UserCreate(BaseModel): ...` |
| `service.py` (또는 `xxx_service.py`) | 복잡한 로직을 라우터에서 분리한 것 | OCR 처리, 가이드 자동 생성 등 |

**모든 도메인에 4개 파일이 다 있는 건 아니에요.** 예를 들어:
- `domains/auth/`는 `router.py`만 있어요 — 로그인/가입은 `User` 모델을 그대로 가져다 쓰기 때문에 자기 모델이 따로 없어요.
- `domains/drug/`도 `router.py` + `service.py`만 있고 모델/스키마가 없어요.
- 대부분의 도메인은 아직 `service.py`가 없고, 로직이 `router.py` 안에 그대로 있어요. (다음 단계로 분리 예정 — 지금 당장 없다고 잘못된 게 아닙니다.)

## 3. 새 기능을 추가할 때

### 3-1. 완전히 새로운 도메인을 추가하는 경우
예: "리뷰(review)" 기능을 새로 만든다면 —

1. **`backend/domains/review/` 폴더 생성**
2. **`backend/domains/review/__init__.py`** — 빈 파일로 생성 (내용 없어도 됨! 이게 정상입니다)
3. **`backend/domains/review/model.py`** — DB 테이블 정의
   ```python
   from sqlalchemy import Column, Integer, String, ForeignKey
   from backend.core.database import Base

   class Review(Base):
       __tablename__ = "reviews"
       id = Column(Integer, primary_key=True, index=True)
       user_id = Column(Integer, ForeignKey("users.id"), nullable=False)
       content = Column(String(500))
   ```
4. **`backend/domains/review/schema.py`** — 요청/응답 형태
   ```python
   from pydantic import BaseModel

   class ReviewCreate(BaseModel):
       content: str

   class ReviewResponse(BaseModel):
       id: int
       user_id: int
       content: str
       class Config:
           from_attributes = True
   ```
5. **`backend/domains/review/router.py`** — 엔드포인트 작성
   ```python
   from fastapi import APIRouter, Depends
   from sqlalchemy.orm import Session
   from backend.core.database import get_db
   from backend.core.dependencies import get_current_user
   from backend.domains.user.model import User
   from .model import Review
   from .schema import ReviewCreate, ReviewResponse

   router = APIRouter()

   @router.post("", response_model=ReviewResponse)
   def create_review(data: ReviewCreate, db: Session = Depends(get_db), current_user: User = Depends(get_current_user)):
       new_review = Review(user_id=current_user.id, content=data.content)
       db.add(new_review)
       db.commit()
       db.refresh(new_review)
       return new_review
   ```
6. **`main.py`에 등록** (파일 맨 위/아래 두 군데 다 추가해야 함)
   ```python
   # 위쪽 import 부분에 추가
   from backend.domains.review import router as review_routers

   # 아래쪽 include_router 부분에 추가
   app.include_router(review_routers.router, prefix="/api/reviews", tags=["리뷰 (Review)"])
   ```
7. 서버 재시작하고 `/docs`에서 새 엔드포인트 보이는지 확인

### 3-2. 이미 있는 도메인에 엔드포인트만 하나 추가하는 경우
예: `record` 도메인에 "진료기록 삭제" 기능 추가

1. `backend/domains/record/router.py`를 열고 함수만 추가하면 끝 (다른 파일 안 건드려도 됨)
   ```python
   @router.delete("/{record_id}")
   def delete_record(record_id: int, db: Session = Depends(get_db), current_user: User = Depends(get_current_user)):
       record = db.query(MedicalRecord).filter(MedicalRecord.id == record_id, MedicalRecord.user_id == current_user.id).first()
       if not record:
           raise HTTPException(status_code=404, detail="기록을 찾을 수 없습니다.")
       db.delete(record)
       db.commit()
       return {"message": "삭제되었습니다."}
   ```
2. 응답 형태가 바뀌면 `schema.py`도 같이 수정
3. `main.py`는 손댈 필요 없음 (이미 등록되어 있는 라우터라서)

## 4. 수정할 때 주의사항

### ⚠️ import 경로 규칙
- **같은 도메인 폴더 안의 파일끼리는 상대경로(`.`)로 가져옵니다.**
  ```python
  from .model import Review        # O
  from .schema import ReviewCreate # O
  ```
- **다른 도메인의 모델/스키마를 가져올 땐 절대경로(`backend.domains.xxx`)로 가져옵니다.**
  ```python
  from backend.domains.user.model import User   # O (record 도메인에서 user 모델 가져오는 예시)
  ```
- **공통 설정(DB, 로그인)은 `backend.core`에서 가져옵니다.**
  ```python
  from backend.core.database import get_db
  from backend.core.dependencies import get_current_user
  ```
- **여러 도메인이 같이 쓰는 유틸은 `backend.utils`에서 가져옵니다.**
  ```python
  from backend.utils.security import get_password_hash
  ```

### ⚠️ `__init__.py`는 비워두는 게 정상입니다
폴더 열었는데 `__init__.py` 안에 아무것도 없어서 "어? 비었네?" 싶을 수 있는데, 이 파일은 "여기가 파이썬 패키지다"라고 표시만 해주는 파일이라 원래 비어있어야 정상이에요. 코드는 `router.py`/`model.py`/`schema.py`에 들어있습니다.

### ⚠️ `main.py`에 두 번 등록해야 새 도메인이 살아납니다
새 도메인 폴더를 아무리 잘 만들어도, `main.py` 위쪽의 `import` 문과 아래쪽의 `app.include_router(...)` 둘 다 추가해야 실제로 API가 열려요. 하나라도 빠지면 서버는 뜨는데 `/docs`에 안 보여요.

### ⚠️ 모델(테이블)을 바꾸면 서버를 재시작해야 반영됩니다
지금은 `Base.metadata.create_all()`이 "테이블이 하나도 없을 때만" 새로 만들어요 (이미 있으면 건드리지 않음). 그래서 기존 테이블의 컬럼을 바꾸고 싶으면:
- 로컬 개발 중이면: DB를 통째로 지우고 재시작 (테스트 데이터라 상관없다면 제일 간단함)
- 이미 실제 데이터가 있으면: Alembic 같은 마이그레이션 도구 필요 (지금은 아직 안 붙어있음)

### ⚠️ 수정 후엔 꼭 `/docs`(Swagger)에서 실제로 호출해보고 커밋하기
문법 에러가 없어도 로직이 깨질 수 있어요. 특히:
- 새 필드를 스키마에 추가했는데 모델엔 안 만든 경우
- `response_model`이랑 실제 반환값 형태가 다른 경우
- 다른 도메인 모델을 참조하는 관계(FK/relationship)를 추가했는데 상대편 모델에 짝을 안 만든 경우 (이거 때문에 예전에 서버 전체가 죽은 적 있어요 — 두 모델 다 확인!)

| record | `/api/records` | 진료기록 CRUD | |
